# Blueprint: Round 2 — edit expenses, category budgets, recurring expenses

- **Repo:** `jyeann/factory-pilot` (React 19 + TS + Vite, localStorage, Vitest)
- **Objective:** add (a) editing an existing expense, (b) monthly budgets per category,
  (c) recurring expenses that create themselves — built by parallel agent sessions,
  one PR each, with no merge conflicts.
- **Status:** draft v2 (after adversarial review) — see "Review log" at the end.

## Strategy

Round 1 showed every parallel PR conflicting in `src/App.tsx`. This round is
**contract-first**: Step 0 lands every shared change (types, state hook, list/form
props, storage helper) **and** wires stub components for each feature into `App.tsx`.
Steps 1–3 then only edit files inside their own `src/features/<name>/` folder, so they
can run fully in parallel and merge in any order. Step 4 integrates and verifies.

```
Step 0 (foundation, serial) ──┬── Step 1 edit-expense ──┐
                              ├── Step 2 budgets ───────┼── Step 4 integrate + verify
                              └── Step 3 recurring ─────┘
```

| Step | Branch | Depends on | Parallel with | Model tier | Executor |
|---|---|---|---|---|---|
| 0 Foundation & contracts | `feature/r2-foundation` | — | — | strongest | orchestrator |
| 1 Edit expense | `feature/edit-expense` | 0 | 2, 3 | default | agent session |
| 2 Category budgets | `feature/budgets` | 0 | 1, 3 | default | agent session |
| 3 Recurring expenses | `feature/recurring` | 0 | 1, 2 | strongest (date logic) | agent session |
| 4 Integrate & verify | `main` | 1, 2, 3 | — | strongest | orchestrator |

### Invariants (checked after every step)
1. `npm test`, `npm run build`, `npm run lint` all pass.
2. Steps 1–3 change **only** files under their own `src/features/<name>/` folder
   (plus new test files there). Any other file in the diff = plan violation; stop and report.
3. Existing localStorage data keeps loading (no key renames; new fields optional).
4. Amounts stay integer cents; dates stay local `YYYY-MM-DD` strings.
5. UI uses the design tokens in `src/index.css` (warm & friendly palette, Bricolage
   Grotesque display / Figtree body, radii `--radius-hero|sheet|control`). No new runtime deps.
6. **Unique accessible names.** App-level tests look up "Amount", "Description", "Add",
   "Total" and "Undo". Feature UIs must never use exactly those names for inputs or
   buttons (use e.g. "Rule amount", "Add rule", "Budget for Food"). The edit dialog only
   renders its form while open.
7. Dates: never `new Date('YYYY-MM-DD')` (parses as UTC). Use the helpers in
   `src/lib/dates.ts`. Known limitation this round: `now` is read at render, so the budget
   month and recurring generation don't roll over at midnight while the app stays open.

## Step 0 — Foundation & contracts (orchestrator, serial)

**Context brief.** Shared code all three features need, plus stubs so feature agents
never edit shared files. Keep every change additive; existing tests must stay green.

**Tasks**
1. `src/types.ts`: add optional `recurringId?: string` to `Expense` (set on expenses
   generated by a recurring rule).
2. `src/lib/storage.ts`: make `isExpense` accept an optional string `recurringId`;
   add generic `loadJson<T>(key, parse: (v: unknown) => T | null, fallback: T, storage?)`
   (`parse` may validate *and clean*, e.g. drop bad entries; null → fallback) and
   `saveJson(key, value, storage?)` with the same try/catch behaviour.
3. `src/lib/expenses.ts`: add pure `updateExpense(list, id, patch: Partial<NewExpense>)`
   — ignores any `id` in the patch, keeps `recurringId`, skips keys whose value is
   `undefined` — and `mergeExpenses(list, incoming: Expense[])` (appends only ids not
   already present).
4. `src/useExpenses.ts`: expose `update(id, patch)` and `addMany(expenses: Expense[])`
   (idempotent by id, uses `mergeExpenses`).
5. `src/lib/money.ts`: add `centsToInput(cents): string` (`1250` → `"12.50"`, the
   inverse of `parseAmountToCents`) for prefilling inputs.
6. `src/lib/dates.ts`: export `parseIsoDate`; add `addDays(iso, n)` and
   `addMonthsClamped(startIso, n)` (start + n months, day clamped to the month's last
   day, leap years handled). `ExpenseForm`'s private `today()` uses `toIsoDate`.
7. `src/components/ExpenseForm.tsx`: keep the prop name `onAdd(expense: NewExpense)`;
   in edit mode it receives all form fields. New optional props: `initial?: NewExpense`
   (read once on mount — callers must remount with a `key` to change it),
   `title?: string` (default "Add an expense"), `submitLabel?: string` (default "Add"),
   `onCancel?: () => void` (renders a "Cancel" ghost button), `resetOnSubmit?: boolean`
   (default true).
8. `src/components/ExpenseList.tsx`: optional `onEdit?: (expense: Expense) => void`
   renders an "Edit <description>" icon button before delete; show a small "Repeats"
   marker (with accessible text) on rows that have `recurringId`.
9. Stubs — each as `<Name>.tsx` (component, renders `null`, final typed props) plus an
   `index.ts` barrel, like `features/search-filter`. Agents edit the `.tsx`, keep the barrel:
   - `features/edit-expense/EditExpenseDialog.tsx` — `{ expense: Expense | null, onSave: (id: string, patch: NewExpense) => void, onClose: () => void }`
   - `features/budgets/BudgetsPanel.tsx` — `{ expenses: Expense[], now?: Date }`
   - `features/recurring/RecurringPanel.tsx` — `{ onGenerate: (expenses: Expense[]) => void, now?: Date }`
10. `src/test-setup.ts`: conditional `HTMLDialogElement.prototype.showModal/close`
    polyfill (jsdom 30 lacks them) and `afterEach(() => localStorage.clear())`.
11. `src/App.test.tsx`: scope form lookups with `within(<the add form>)` so feature UIs
    can't make them ambiguous.
12. `src/App.tsx`: wire them once: `editing` state + `onEdit={setEditing}` on the list,
   `<EditExpenseDialog expense={editing} onSave={update} onClose={() => setEditing(null)} />`,
   `<BudgetsPanel expenses={expenses} />` right after `<MonthlySummary>`,
   `<RecurringPanel onGenerate={addMany} />` after `<ExpenseForm>`.
13. `CLAUDE.md`: add a "Round 2" note — feature agents edit only their folder; stubs'
    prop signatures are the contract and must not change; invariants 6–7.
14. Tests for `updateExpense` (incl. keeps `recurringId`), `mergeExpenses`, storage
    helpers, `centsToInput`, date helpers (31st clamping, leap year), list Edit button,
    form `initial`/`onCancel`.

**Verify:** invariants 1, 3. App looks unchanged except Edit buttons (no-op until Step 1).
**Exit:** PR merged to `main`.  **Rollback:** revert the merge commit.

## Step 1 — Edit expense (agent, parallel)

**Context brief.** Users can fix a typo'd amount, category or date. `App.tsx` already
renders `<EditExpenseDialog expense onSave onClose />` from
`src/features/edit-expense/index.ts`; clicking a row's Edit button sets `expense`.
Implement the component only.

**Tasks**
1. Use a native `<dialog>`; an effect calls `showModal()` when `expense` becomes
   non-null and `close()` when it becomes null. Handle the dialog's `onCancel` (Escape)
   and `onClose` events and backdrop clicks by calling `onClose()` — otherwise React state
   stays set and the dialog can't reopen for the same row.
2. Render the shared `ExpenseForm` **only while `expense` is set**, with
   `key={expense.id}` (it reads `initial` once), `initial` = the expense's fields,
   `title="Edit expense"`, `submitLabel="Save changes"`, `resetOnSubmit={false}`,
   `onCancel={onClose}`; its `onAdd(fields)` calls `onSave(expense.id, fields)` then `onClose()`.
3. Return focus to the Edit button that opened it (store `document.activeElement`).
4. Styles in `edit-expense.css` using tokens (sheet radius, plum backdrop at ~40%).
5. Tests: opens with values prefilled (amount via `centsToInput`); save calls `onSave`
   with all form fields; Cancel and Escape call `onClose`; switching to another expense
   shows its values; validation errors still shown. The dialog polyfill is already in
   `src/test-setup.ts`.

**Verify:** invariants 1–2.  **Exit:** PR "feat: edit expenses" open, checks green.

## Step 2 — Monthly budgets per category (agent, parallel)

**Context brief.** Users set a monthly limit per category and see how this month is
going. `App.tsx` renders `<BudgetsPanel expenses={expenses} />` under the sunflower
hero. Implement inside `src/features/budgets/` only.

**Tasks**
1. Data: `Budgets = Record<categoryId, amountCents>`; persist with `loadJson/saveJson`
   under key `factory-pilot.budgets.v1`; the `parse` function drops non-positive /
   non-integer values. Editor inputs prefill with `centsToInput`, parse with
   `parseAmountToCents`. Input names: "Budget for <Category>"; button "Save budgets".
   Recurring-generated expenses count like any other.
2. Pure helpers (`budgets.ts`): `budgetStatus(expenses, budgets, month)` →
   per budgeted category `{ category, spentCents, limitCents, ratio, state: 'ok'|'near'|'over' }`
   (`near` ≥ 80%). Use the current month (`now` prop for tests).
3. UI: a sheet titled "Budgets" listing budgeted categories with a progress bar in the
   category colour (`categoryColor`), "$32 of $200", and an over-budget message in
   `--danger` ("$12 over"). Collapsed "Set budgets" editor: one money input per category,
   blank = no budget, Save. Empty state: one line inviting the user to set a budget.
4. Accessible: progress conveyed in text, not only colour; inputs labelled per category.
5. Tests: helper math incl. no budgets, over/near thresholds, other months ignored;
   editor saves and persists; panel shows over-budget text.

**Verify:** invariants 1–2.  **Exit:** PR "feat: category budgets" open, checks green.

## Step 3 — Recurring expenses (agent, parallel)

**Context brief.** Rent, subscriptions etc. should appear automatically. `App.tsx`
renders `<RecurringPanel onGenerate={addMany} />`; `addMany` is idempotent by expense id.
Expenses carry an optional `recurringId`. Implement inside `src/features/recurring/` only.

**Tasks**
1. Rule model: `{ id, description, amountCents, category, frequency: 'monthly'|'weekly',
   startDate: 'YYYY-MM-DD', generatedThrough: 'YYYY-MM-DD' | null }`, persisted with
   `loadJson/saveJson` under `factory-pilot.recurring.v1`.
2. Pure `dueOccurrences(rule, today)`: occurrence dates `d` with
   `d >= startDate` **and** (`generatedThrough === null` or `d > generatedThrough`)
   **and** `d <= today`. Monthly: `addMonthsClamped(startDate, n)` for n = 0,1,2…
   (always computed from `startDate`, never from the previous occurrence, so the 31st
   doesn't drift to the 28th). Weekly: `addDays(startDate, 7n)`. Cap at 366 per run.
   A start date in the past backfills every occurrence up to today (up to the cap).
3. Generated expense id is deterministic: `rec:<ruleId>:<date>`, with `recurringId`
   set. After a run, set `generatedThrough` to the **last date actually generated**
   (leave it unchanged when nothing was due), so capped runs continue next time and a
   deleted occurrence is **not** recreated.
4. Run generation in a `useEffect` on mount and when rules change (never inside a
   `setState` updater). `main.tsx` uses StrictMode, so effects run twice in dev: make the
   run idempotent — compute from the current rules, call `onGenerate(list)` once if
   non-empty, then save the advanced rules; ids dedupe any repeat.
5. UI: "Repeating expenses" sheet: list rules ("Rent, $1,200 every month on the 1st" —
   words, not middle dots), add-rule form with names "Rule description", "Rule amount",
   "Rule category", "Repeats", "Starts on", button "Add rule"; delete rule ("Delete rule
   Rent") keeps already-created expenses. No rule editing this round.
6. Tests (fixed `now`): monthly incl. 31st clamping and leap year; weekly; nothing due
   before start; past start backfills; cap continues next run; generatedThrough prevents
   regeneration after delete; panel calls `onGenerate` once.

**Verify:** invariants 1–2.  **Exit:** PR "feat: recurring expenses" open, checks green.

## Step 4 — Integrate & verify (orchestrator, serial)

**Tasks**
1. Review each PR diff against its step (scope = own folder only) and invariants.
2. Merge 1, 2, 3 in any order (expected: no conflicts). If one conflicts, stop and
   find which invariant was broken.
3. Cross-feature checks in a browser: edit a recurring-generated expense (keeps its
   `recurringId`, budget updates); delete one (not regenerated on reload); budgets
   reflect edits immediately; dark mode and 390px mobile look right.
4. Full test/build/lint on `main`, rebuild (`base: './'`), republish the test site,
   update `FACTORY.md` with round-2 notes and cost/time.

## Plan mutation protocol
- **Split** a step if its PR exceeds ~500 changed lines (excluding tests).
- **Skip** a step: record why here; Step 4 ignores it.
- **Contract change needed** (a stub prop is insufficient): the agent stops and reports;
  the orchestrator lands a small follow-up to Step 0 first. Agents never edit shared files.
